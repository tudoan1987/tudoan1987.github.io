Shift-left Security:
Tích hợp bảo mật vào CI/CD Pipeline

Tu Doan Minh Dec 2025 9 min read

Penetration test mỗi quý một lần không còn đủ. Khi team deploy 20+ lần/ngày, bảo mật phải nằm trong pipeline — không phải sau nó. Đây là security pipeline tôi đã build, chạy dưới 4 phút và block được 95% vulnerabilities trước khi vào production.

Security Gates trong CI/CD

Git Push
   │
   ▼
① SAST — SonarQube (code vulnerabilities)
   │  fail → block PR
   ▼
② Secrets Scan — Gitleaks (hardcoded credentials)
   │  fail → block immediately + alert
   ▼
③ Dependency Scan — Trivy (CVE trong packages)
   │  CRITICAL CVE → block; HIGH → warn
   ▼
④ Container Scan — Trivy (image vulnerabilities)
   │  fail → block deployment
   ▼
⑤ IaC Scan — tfsec / Checkov (misconfigs)
   │  fail → block PR
   ▼
⑥ Image Signing — Cosign (supply chain integrity)
   │
   ▼
 Deploy (chỉ signed images mới được admit)

① SAST với SonarQube

# .github/workflows/security.yml
- name: SonarQube Scan
  uses: SonarSource/sonarqube-scan-action@v3
  env:
    SONAR_TOKEN: ${{ secrets.SONAR_TOKEN }}
    SONAR_HOST_URL: ${{ secrets.SONAR_HOST_URL }}

- name: Quality Gate Check
  uses: SonarSource/sonarqube-quality-gate-action@v1
  with:
    scanMetadataReportFile: .scannerwork/report-task.txt
  # Fail nếu: new bugs > 0, new vulnerabilities > 0,
  #           new code coverage < 80%

② Secrets Scanning với Gitleaks

Gitleaks scan toàn bộ git history, không chỉ commit mới nhất: 

- name: Gitleaks Secret Scan
  uses: gitleaks/gitleaks-action@v2
  env:
    GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
    GITLEAKS_LICENSE: ${{ secrets.GITLEAKS_LICENSE }}

Nếu phát hiện secret đã commit: rotate ngay lập tức, sau đó mới xử lý git history. Đừng bao giờ nghĩ rằng "xóa commit là xong" — secret đã leak rồi.

Trong 2 năm qua tôi đã thấy 3 incident từ hardcoded AWS keys. Cả 3 đều phát hiện sau khi key đã bị abuse. Gitleaks pre-commit hook ngăn được điều này từ đầu.

③④ Container Scanning với Trivy

- name: Build Image
  run: docker build -t app:${{ github.sha }} .

- name: Trivy — Filesystem Scan (dependencies)
  uses: aquasecurity/trivy-action@master
  with:
    scan-type: fs
    scan-ref: .
    severity: CRITICAL,HIGH
    exit-code: 1           # fail CI nếu có CRITICAL
    ignore-unfixed: true   # bỏ qua CVE chưa có fix

- name: Trivy — Image Scan
  uses: aquasecurity/trivy-action@master
  with:
    image-ref: app:${{ github.sha }}
    severity: CRITICAL
    exit-code: 1
    format: sarif
    output: trivy-results.sarif

- name: Upload to GitHub Security tab
  uses: github/codeql-action/upload-sarif@v3
  with:
    sarif_file: trivy-results.sarif

⑥ Image Signing với Cosign

Chỉ images đã được sign mới được deploy — enforce bởi OPA Gatekeeper trên Kubernetes: 

# Sign sau khi push lên registry
- name: Sign Container Image
  run: |
    cosign sign --yes \
      --key env://COSIGN_PRIVATE_KEY \
      ${{ env.REGISTRY }}/app@${{ steps.build.outputs.digest }}
  env:
    COSIGN_PRIVATE_KEY: ${{ secrets.COSIGN_PRIVATE_KEY }}
    COSIGN_PASSWORD: ${{ secrets.COSIGN_PASSWORD }}
# OPA Gatekeeper policy — chỉ admit signed images
apiVersion: constraints.gatekeeper.sh/v1beta1
kind: RequireSignedImages
metadata:
  name: require-signed-images
spec:
  match:
    kinds:
    - apiGroups: [""]
      kinds: ["Pod"]
    namespaces: ["production", "staging"]
  parameters:
    publicKey: "-----BEGIN PUBLIC KEY-----\n..."

Kết quả sau 6 tháng

  • 0 CVE severity CRITICAL vào production (từ 4-5 incidents/quý trước đó)
  • Pipeline security time: trung bình 3m 20s — không ảnh hưởng đến developer velocity
  • 12 secrets bị chặn trước khi commit vào main branch
  • Supply chain attack surface giảm nhờ image signing + admission control

Bắt đầu từ đâu nếu chưa có gì?

Thứ tự ưu tiên nếu bạn đang bắt đầu từ zero:

  1. Secrets scanning — ROI cao nhất, setup nhanh nhất
  2. Dependency CVE scan — Trivy hoặc Snyk, chạy được ngay
  3. Container image scan — trước khi push lên registry
  4. SAST — cần thời gian tune rules để giảm false positives
  5. Image signing — làm sau khi 4 cái trên đã ổn định
