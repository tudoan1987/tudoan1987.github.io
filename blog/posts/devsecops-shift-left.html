Integrating Security into CI/CD Pipelines

Tu Doan Minh Dec 2025 9 min read

Penetration test mỗi quý một lần không còn đủ. Khi team deploy 20+ lần/ngày, bảo mật phải nằm trong pipeline — không phải sau nó. Đây là security pipeline tôi đã build, chạy dưới 4 phút và block được 95% vulnerabilities trước khi vào production.

Security Gates trong CI/CD

Git Push → ① SAST (SonarQube) → ② Secrets Scan (Gitleaks)
         → ③ Dependency Scan (Trivy) → ④ Container Scan (Trivy)
         → ⑤ IaC Scan (tfsec) → ⑥ Image Signing (Cosign)
         → Deploy (chỉ signed images được admit)

① SAST với SonarQube

- name: SonarQube Scan
  uses: SonarSource/sonarqube-scan-action@v3
  env:
    SONAR_TOKEN: ${{ secrets.SONAR_TOKEN }}

- name: Quality Gate Check
  uses: SonarSource/sonarqube-quality-gate-action@v1
  # Fail nếu: new bugs > 0, new vulnerabilities > 0

② Secrets Scanning với Gitleaks

- name: Gitleaks Secret Scan
  uses: gitleaks/gitleaks-action@v2
  env:
    GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
Trong 2 năm qua tôi đã thấy 3 incident từ hardcoded AWS keys. Cả 3 đều phát hiện sau khi key đã bị abuse. Gitleaks pre-commit hook ngăn được điều này từ đầu.

③④ Container Scanning với Trivy

- name: Trivy — Image Scan
  uses: aquasecurity/trivy-action@master
  with:
    image-ref: app:${{ github.sha }}
    severity: CRITICAL
    exit-code: 1
    format: sarif
    output: trivy-results.sarif

⑥ Image Signing với Cosign

- name: Sign Container Image
  run: |
    cosign sign --yes \
      --key env://COSIGN_PRIVATE_KEY \
      ${{ env.REGISTRY }}/app@${{ steps.build.outputs.digest }}
  env:
    COSIGN_PRIVATE_KEY: ${{ secrets.COSIGN_PRIVATE_KEY }}

Kết quả sau 6 tháng

  • 0 CVE severity CRITICAL vào production (từ 4-5 incidents/quý trước đó)
  • Pipeline security time: trung bình 3m 20s
  • 12 secrets bị chặn trước khi commit vào main branch

Bắt đầu từ đâu?

  1. Secrets scanning — ROI cao nhất, setup nhanh nhất
  2. Dependency CVE scan — Trivy hoặc Snyk, chạy được ngay
  3. Container image scan — trước khi push lên registry
  4. SAST — cần thời gian tune rules để giảm false positives
  5. Image signing — làm sau khi 4 cái trên đã ổn định

A quarterly penetration test is no longer enough. When your team deploys 20+ times per day, security must be inside the pipeline — not after it. Here's the security pipeline I built that runs in under 4 minutes and blocks 95% of vulnerabilities before they reach production.

Security gates in CI/CD

Git Push → ① SAST (SonarQube) → ② Secrets Scan (Gitleaks)
         → ③ Dependency Scan (Trivy) → ④ Container Scan (Trivy)
         → ⑤ IaC Scan (tfsec) → ⑥ Image Signing (Cosign)
         → Deploy (only signed images admitted)

① SAST with SonarQube

- name: SonarQube Scan
  uses: SonarSource/sonarqube-scan-action@v3
  env:
    SONAR_TOKEN: ${{ secrets.SONAR_TOKEN }}

- name: Quality Gate Check
  uses: SonarSource/sonarqube-quality-gate-action@v1
  # Fail if: new bugs > 0, new vulnerabilities > 0

② Secrets scanning with Gitleaks

- name: Gitleaks Secret Scan
  uses: gitleaks/gitleaks-action@v2
  env:
    GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
Over the past two years I've seen three incidents caused by hardcoded AWS keys. All three were discovered after the key had already been abused. A Gitleaks pre-commit hook prevents this from the start.

Results after 6 months

  • Zero CRITICAL CVEs reaching production (down from 4-5 incidents per quarter)
  • Average security pipeline time: 3m 20s
  • 12 secrets blocked before they reached the main branch

Where to start?

  1. Secrets scanning — highest ROI, fastest to set up
  2. Dependency CVE scan — Trivy or Snyk, runs immediately
  3. Container image scan — before pushing to registry
  4. SAST — needs time to tune rules and reduce false positives
  5. Image signing — do this once the above four are stable
