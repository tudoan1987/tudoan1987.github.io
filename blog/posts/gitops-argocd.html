GitOps với ArgoCD:
Deploy Kubernetes không còn lo sợ GitOps with ArgoCD:
Fearless Kubernetes Deployments

Tu Doan Minh Nov 2025 8 min read

Trước khi dùng GitOps, mỗi lần deploy production là một sự kiện căng thẳng — ai đó chạy kubectl apply trên laptop, không ai biết cluster đang ở trạng thái gì, rollback là một mớ lệnh gõ tay trong panic. Sau khi migrate sang ArgoCD, deploy trở thành boring — và đó chính xác là điều bạn muốn.

GitOps là gì

GitOps = Git là single source of truth cho infrastructure và application state. Bất kỳ thay đổi nào trên cluster đều phải đi qua Git commit.

  • ✅ Developer push code → CI build image → update image tag trong Git → ArgoCD sync
  • ❌ Không ai được kubectl edit hay helm upgrade trực tiếp trên production
Nếu bạn vẫn còn kubectl apply -f trực tiếp lên production, bạn chưa làm GitOps — bạn đang làm "Git lưu file YAML".

App of Apps Pattern

gitops-repo/
├── apps/                        # App of Apps root
│   ├── Chart.yaml
│   ├── values-dev.yaml
│   ├── values-prod.yaml
│   └── templates/
│       ├── api-service.yaml
│       └── frontend.yaml
└── services/
    ├── api-service/{dev,staging,prod}/
    └── frontend/...
apiVersion: argoproj.io/v1alpha1
kind: Application
metadata:
  name: api-service-{{ .Values.environment }}
spec:
  source:
    path: services/api-service/{{ .Values.environment }}
  syncPolicy:
    automated:
      prune: true       # xóa resources không còn trong Git
      selfHeal: true    # auto-revert manual changes trên cluster

CI chỉ update Git — ArgoCD làm phần còn lại

- name: Update image tag in GitOps repo
  run: |
    yq e '.image.tag = "${{ github.sha }}"' \
      -i services/api-service/dev/values.yaml
    git add . && git commit -m "chore: deploy api-service ${{ github.sha }}"
    git push

Secrets với Sealed Secrets

kubeseal --format yaml \
  --controller-name=sealed-secrets \
  < secret.yaml > sealed-secret.yaml
# sealed-secret.yaml an toàn để commit vào Git

Kết quả sau 1 năm

  • Deploy frequency tăng 3x — deploy nhiều hơn vì ít sợ hơn
  • MTTR từ 45 phút xuống 8 phút
  • Zero "surprise" cluster state — mọi thứ đều có trong Git history
  • Onboarding engineer mới: từ 2 tuần học deploy process xuống 2 ngày

GitOps không phải tool — là văn hoá. ArgoCD chỉ là enforcement mechanism. Thứ quan trọng hơn là team đồng ý: Git là sự thật, không phải cluster.

Before GitOps, every production deployment was a stressful event — someone running kubectl apply from their laptop, nobody knowing what state the cluster was actually in, and rollback meant frantically typing commands in a panic. After migrating to ArgoCD, deployments became boring — and that's exactly what you want.

What GitOps actually means

GitOps = Git is the single source of truth for infrastructure and application state. Every change to the cluster must go through a Git commit.

  • ✅ Developer pushes code → CI builds image → updates image tag in Git → ArgoCD syncs
  • ❌ Nobody runs kubectl edit or helm upgrade directly on production
If you're still running kubectl apply -f directly against production, you're not doing GitOps — you're doing "Git stores YAML files".

Results after one year

  • Deploy frequency increased 3x — teams deploy more because they fear it less
  • MTTR dropped from 45 minutes to 8 minutes
  • Zero "surprise" cluster state — everything is in Git history
  • New engineer onboarding: from two weeks learning the deploy process to two days

GitOps isn't a tool — it's a culture. ArgoCD is just the enforcement mechanism. What matters more is the team agreement: Git is the truth, not the cluster.
