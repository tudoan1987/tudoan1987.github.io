MLflow + Kubernetes:
MLOps Pipeline từ A đến Z MLflow + Kubernetes:
End-to-End MLOps Pipeline

Tu Doan Minh Feb 2026 10 min read

"Model của tôi train xong rồi, giờ deploy lên production như thế nào?" — câu hỏi này tôi nghe ít nhất một lần mỗi tuần. Bài này là câu trả lời đầy đủ: một MLOps platform tôi đã build và vận hành thực tế, từ experiment đến production monitoring.

Kiến trúc tổng thể

Data → Feature Store (Feast) → Training (MLflow) → Registry → Serving (KServe)
                                                                     ↓
                                              Monitoring (Prometheus + Evidently)

MLflow trên Kubernetes

apiVersion: apps/v1
kind: Deployment
metadata:
  name: mlflow-tracking
  namespace: mlops
spec:
  replicas: 2
  template:
    spec:
      containers:
      - name: mlflow
        image: ghcr.io/mlflow/mlflow:2.11.0
        args:
          - mlflow
          - server
          - --backend-store-uri=postgresql://$(DB_USER):$(DB_PASS)@postgres:5432/mlflow
          - --default-artifact-root=gs://my-mlflow-artifacts

Training Pipeline với Kubeflow Pipelines

@dsl.pipeline(name="fraud-detection-training")
def training_pipeline(data_version: str = "v20260201"):
    preprocess = preprocess_data(data_version=data_version)
    train = train_model(
        data_path=preprocess.outputs["output_data"],
        model_name="fraud-detector",
        mlflow_uri="http://mlflow-tracking.mlops:5000"
    )
    evaluate = evaluate_and_register(
        model=train.outputs["output_model"],
        threshold=0.90
    )

Canary Deployment với KServe + Istio

apiVersion: serving.kserve.io/v1beta1
kind: InferenceService
metadata:
  name: fraud-detector
spec:
  predictor:
    model:
      storageUri: gs://models/fraud-detector/v2
  canaryTrafficPercent: 10
  canary:
    predictor:
      model:
        storageUri: gs://models/fraud-detector/v3

Drift Detection và Auto-rollback

def check_drift_and_rollback(reference_data, current_data):
    report = Report(metrics=[DataDriftPreset()])
    report.run(reference_data=reference_data, current_data=current_data)
    if report.as_dict()["metrics"][0]["result"]["dataset_drift"]:
        trigger_argocd_rollback()
Auto-rollback đã cứu production 2 lần trong 6 tháng đầu — một lần do data pipeline thay đổi schema, một lần do seasonal drift không lường trước.

Lessons Learned

  • Feature store (Feast) loại bỏ training/serving skew ngay từ đầu
  • Log input data cùng với prediction — không có nó, debug production issues gần như impossible
  • Canary nhỏ (5-10%) ít nhất 24h trước khi full rollout
  • Mọi production model phải có owner, expiry date và fallback plan

"My model is trained, how do I deploy it to production?" — a question I hear at least once a week. This post is the full answer: an MLOps platform I've built and operated in production, from experiment to production monitoring.

Overall architecture

Data → Feature Store (Feast) → Training (MLflow) → Registry → Serving (KServe)

                                              Monitoring (Prometheus + Evidently)

Drift detection and auto-rollback

def check_drift_and_rollback(reference_data, current_data):
    report = Report(metrics=[DataDriftPreset()])
    report.run(reference_data=reference_data, current_data=current_data)
    if report.as_dict()["metrics"][0]["result"]["dataset_drift"]:

Auto-rollback saved production twice in the first six months — once from a data pipeline schema change, once from unexpected seasonal drift.

Lessons learned

  • Feature store (Feast) eliminates training/serving skew from day one
  • Log input data alongside predictions — without it, debugging production issues is near impossible
  • Keep canary small (5-10%) for at least 24h before full rollout
  • Every production model needs an owner, expiry date, and fallback plan
