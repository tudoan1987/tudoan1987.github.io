FinOps cho Multi-cloud:
Giảm 40% chi phí AWS + GCP Multi-cloud FinOps:
40% Cost Reduction on AWS + GCP

Tu Doan Minh Mar 2026 6 min read

Cloud bill tháng 3 vừa rồi của team tôi: giảm 41% so với tháng 12/2025 — từ $28,000 xuống còn $16,500/tháng. Không phải vì chúng tôi dùng ít hơn, mà vì chúng tôi cuối cùng đã làm FinOps đúng cách. Đây là những gì đã thực sự tạo ra sự khác biệt.

Bước 1: Visibility — Bạn không thể tối ưu cái bạn không nhìn thấy

Trước khi cắt bất kỳ chi phí nào, phải biết tiền đang chạy đi đâu. Tôi setup cost allocation với tags bắt buộc trên mọi resource:

variable "required_tags" {
  type = map(string)
  default = {
    Environment = "required"
    Team        = "required"
    Project     = "required"
    CostCenter  = "required"
  }
}

Sau đó dùng AWS Cost Explorer + GCP BigQuery billing export để build dashboard Grafana thống nhất — nhìn cả 2 cloud trên 1 màn hình.

Bước 2: Right-sizing — Quick win lớn nhất

Chạy AWS Compute Optimizer và GCP Recommender report, tôi phát hiện: 67% EC2 instances đang over-provisioned — average CPU utilization chỉ 12%. Script tìm orphaned EBS volumes:

aws ec2 describe-volumes \
  --filters Name=status,Values=available \
  --query 'Volumes[*].{ID:VolumeId,Size:Size,Created:CreateTime}' \
  --output table
Right-sizing EC2 và xóa orphaned resources đã tiết kiệm $4,200/tháng chỉ trong tuần đầu tiên.

Bước 3: Reserved Instances và Savings Plans

Sau khi right-size xong, mới commit Reserved Instances. Chiến lược của tôi:

  • Compute Savings Plans (AWS): 60% workload ổn định → 1-year, no upfront
  • EC2 Instance Savings Plans: Database servers → 3-year, partial upfront
  • GCP Committed Use Discounts: GKE node pools cố định → 1-year CUD
  • Spot/Preemptible: Batch jobs, CI/CD runners → 70-80% discount

Bước 4: Automated Shutdown — Dev/Staging ngoài giờ

resource "aws_cloudwatch_event_rule" "stop_dev" {
  name                = "stop-dev-environments"
  schedule_expression = "cron(0 13 ? * MON-FRI *)"  # 20:00 ICT
}
resource "aws_cloudwatch_event_rule" "start_dev" {
  name                = "start-dev-environments"
  schedule_expression = "cron(0 1 ? * MON-FRI *)"   # 08:00 ICT
}

Kết quả: dev/staging chạy 55 giờ/tuần thay vì 168 giờ — tiết kiệm 67% chi phí cho những environment này.

Kết quả sau 3 tháng

  • AWS: -38% ($18k → $11k/tháng)
  • GCP: -47% ($10k → $5.3k/tháng)
  • Không service nào bị downgrade về performance

FinOps không phải là cắt giảm — là spending đúng chỗ. Mục tiêu không phải zero cost, mà là mỗi dollar phải tạo ra value tương xứng.

Our team's cloud bill for March: down 41% compared to December 2025 — from $28,000 to $16,500/month. Not because we used less, but because we finally did FinOps properly. Here's what actually made the difference.

Step 1: Visibility — You can't optimize what you can't see

Before cutting any costs, you need to know where the money is going. I set up cost allocation with mandatory tags on every resource:

variable "required_tags" {
  type = map(string)
  default = {
    Environment = "required"
    Team        = "required"
    Project     = "required"
    CostCenter  = "required"
  }
}

Then used AWS Cost Explorer + GCP BigQuery billing export to build a unified Grafana dashboard — both clouds on one screen.

Step 2: Right-sizing — The biggest quick win

Running AWS Compute Optimizer and GCP Recommender reports, I found that 67% of EC2 instances were over-provisioned — average CPU utilization was just 12%. Script to find orphaned EBS volumes:

aws ec2 describe-volumes \
  --filters Name=status,Values=available \
  --query 'Volumes[*].{ID:VolumeId,Size:Size,Created:CreateTime}' \
  --output table
Right-sizing EC2 and deleting orphaned resources saved $4,200/month in the first week alone.

Step 3: Reserved Instances and Savings Plans

Right-size first, then commit to Reserved Instances. My strategy:

  • Compute Savings Plans (AWS): 60% stable workload → 1-year, no upfront
  • EC2 Instance Savings Plans: Database servers → 3-year, partial upfront
  • GCP Committed Use Discounts: Fixed GKE node pools → 1-year CUD
  • Spot/Preemptible: Batch jobs, CI/CD runners → 70-80% discount

Step 4: Automated Shutdown — Dev/Staging off-hours

resource "aws_cloudwatch_event_rule" "stop_dev" {
  name                = "stop-dev-environments"
  schedule_expression = "cron(0 13 ? * MON-FRI *)"  # 20:00 ICT
}
resource "aws_cloudwatch_event_rule" "start_dev" {
  name                = "start-dev-environments"
  schedule_expression = "cron(0 1 ? * MON-FRI *)"   # 08:00 ICT
}

Result: dev/staging runs 55 hours/week instead of 168 — saving 67% on those environment costs.

Results after 3 months

  • AWS: -38% ($18k → $11k/month)
  • GCP: -47% ($10k → $5.3k/month)
  • Zero service performance degradations

FinOps isn't about cutting — it's about spending in the right places. The goal isn't zero cost; it's ensuring every dollar delivers proportional value.
