FinOps cho Multi-cloud:
Giảm 40% chi phí AWS + GCP

Tu Doan Minh Mar 2026 6 min read

Cloud bill tháng 3 vừa rồi của team tôi: giảm 41% so với tháng 12/2025 — từ $28,000 xuống còn $16,500/tháng. Không phải vì chúng tôi dùng ít hơn, mà vì chúng tôi cuối cùng đã làm FinOps đúng cách. Đây là những gì đã thực sự tạo ra sự khác biệt.

Bước 1: Visibility — Bạn không thể tối ưu cái bạn không nhìn thấy

Trước khi cắt bất kỳ chi phí nào, phải biết tiền đang chạy đi đâu. Tôi setup cost allocation với tags bắt buộc trên mọi resource: 

# Terraform — enforce mandatory tags
variable "required_tags" {
  type = map(string)
  default = {
    Environment = "required"
    Team        = "required"
    Project     = "required"
    CostCenter  = "required"
  }
}

resource "aws_instance" "app" {
  # ...
  tags = merge(var.required_tags, {
    Name = "app-server"
  })

  lifecycle {
    precondition {
      condition     = length(var.required_tags) == 4
      error_message = "All required tags must be set."
    }
  }
}

Sau đó dùng AWS Cost Explorer + GCP BigQuery billing export để build dashboard Grafana thống nhất — nhìn cả 2 cloud trên 1 màn hình.

Bước 2: Right-sizing — Quick win lớn nhất

Chạy AWS Compute Optimizer và GCP Recommender report, tôi phát hiện:

  • 67% EC2 instances đang over-provisioned — average CPU utilization chỉ 12%
  • 40% RDS instances dùng multi-AZ cho môi trường staging (không cần thiết)
  • Hàng chục EBS volumes orphaned — không attach vào instance nào nhưng vẫn tính tiền

Script tìm orphaned EBS volumes: 

aws ec2 describe-volumes \
  --filters Name=status,Values=available \
  --query 'Volumes[*].{ID:VolumeId,Size:Size,Created:CreateTime}' \
  --output table
Right-sizing EC2 và xóa orphaned resources đã tiết kiệm $4,200/tháng chỉ trong tuần đầu tiên.

Bước 3: Reserved Instances và Savings Plans

Sau khi right-size xong, mới commit Reserved Instances — không làm ngược lại. Nhiều team mắc lỗi mua RI cho instance type sai rồi mắc kẹt 1–3 năm.

Chiến lược của tôi:

  • Compute Savings Plans (AWS): 60% workload ổn định → 1-year, no upfront
  • EC2 Instance Savings Plans: Database servers → 3-year, partial upfront
  • GCP Committed Use Discounts: GKE node pools cố định → 1-year CUD
  • Spot/Preemptible: Batch jobs, CI/CD runners → 70-80% discount

Bước 4: Automated Shutdown — Dev/Staging ngoài giờ

Dev và staging environments không cần chạy 24/7. Tôi viết Lambda function tự động stop/start theo schedule: 

# EventBridge rule — stop dev at 20:00, start at 08:00 weekdays
resource "aws_cloudwatch_event_rule" "stop_dev" {
  name                = "stop-dev-environments"
  schedule_expression = "cron(0 13 ? * MON-FRI *)"  # 20:00 ICT
}

resource "aws_cloudwatch_event_rule" "start_dev" {
  name                = "start-dev-environments"
  schedule_expression = "cron(0 1 ? * MON-FRI *)"   # 08:00 ICT
}

Kết quả: dev/staging chạy 55 giờ/tuần thay vì 168 giờ — tiết kiệm 67% chi phí cho những environment này.

Bước 5: FinOps Culture — Quan trọng hơn tooling

Tool không giải quyết được vấn đề nếu team không quan tâm đến cost. Những thay đổi văn hoá tôi implement:

  • Weekly cost review trong sprint planning — mỗi team thấy bill của mình
  • Cost anomaly alerts qua Slack khi spending tăng >20% trong 24h
  • "Cost champion" trong mỗi squad — người chịu trách nhiệm theo dõi
  • Budget tagging là điều kiện để merge PR infrastructure

Kết quả sau 3 tháng

  • AWS: -38% ($18k → $11k/tháng)
  • GCP: -47% ($10k → $5.3k/tháng)
  • Không service nào bị downgrade về performance
  • Engineer awareness về cost tăng rõ rệt

FinOps không phải là cắt giảm — là spending đúng chỗ. Mục tiêu không phải zero cost, mà là mỗi dollar phải tạo ra value tương xứng.
